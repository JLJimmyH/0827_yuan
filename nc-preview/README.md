# NC 預演台

Fanuc 加工中心 G-code 的網頁版預演、檢錯與編輯工具。純前端：Chrome／Edge 直接開 `index.html`（`file://` 可），不裝套件、不連外，程式檔不離開這台電腦。

> **預演，不是機台模擬器。** 刀長補正（H）當 0、G54–G59 視為同一原點、只支援 G17 平面、不算加減速與前瞻。**上機前的 dry run 照做。**

---

## 怎麼用

| | 做什麼 |
|---|---|
| **1 開檔** | 按「開檔…」或把檔案拖進視窗。編碼自動判斷（UTF-8 → Big5），沒有副檔名也可以 |
| **2 刀具表** | 填實際直徑。用 G41／G42 的**一定要填 D 值**；倒角刀的補正量取決於刀尖高度，只能手填 |
| **3 素材** | Project → 素材填真實尺寸。沒填就用切削範圍推估，靠素材的檢查（撞刀、重切削、廢料）一律降成警告 |
| **4 看結果** | 右下「錯誤清單」，37 條規則。點路徑或點錯誤都會跳到那一行 |

刀具表每格會標這個值是哪來的：`註解`／`動作`／`預設`／`手填` —— 看到`預設`就是猜的，成品圖會不準。刀具表與設定存在瀏覽器（以程式 O 號為 key），下次開同一支自動帶回。

編輯器改完按「存檔」用**原本的檔名**下載（行尾維持原檔的 CRLF／LF），「複製」是整支複製到剪貼簿。停手約 0.3 秒重跑路徑與檢查、1 秒重跑材料模擬。

### 左欄 Project：五個子頁

| 子頁 | 內容 |
|---|---|
| 程式 | 編輯器：行號、錯誤標記、每行的執行摘要（`G1 90 G41D11 F150 Z-2`） |
| 素材 | 形狀（長方體／立圓柱／躺圓柱）、尺寸、原點位置、夾具、廢料判定；跟著程式存 |
| 刀具表 | T 號、型式（22 種）、直徑、角度、刃長、角R／頸徑、D 號與補正值、來源標記；CSV 匯出入 |
| 刀庫 | 刀位配置與大徑刀鄰位檢查；整台機共用 |
| 機台 | 第四軸裝夾、Block skip 細節、換刀前是否需要 M5、G0 速率、下刀進給上限、補正先讀節數、模擬格距 |

### 右下狀態條：四個分頁

**總覽**（程式／素材／刀具／刀庫／機台各一列，點一列跳到對應子頁；分頁列右端的徽章是同一份資料的縮寫）｜**游標行**（那一行**執行後**的完整模態）｜**作業摘要**（以換刀 M6 分段：刀具、H／D、判斷出來的用途、最深 Z、F、S、行號範圍、估計時間）｜**錯誤清單**（嚴重度篩選、只看 skip ON 差異、文字搜尋；同一原因發生在很多行會摺成一列標 `×17`，展開看得到全部行號，少數規則附「套用修正」）。

左右、上下兩條分隔線都可以拖（雙擊回預設），比例會記住。

### 視圖

- **俯視**：色階＝切削深度（淺＝接近頂面）。**白灰棋盤＝切穿或本來沒料**，不是切得很深。
- **剖面 X／Y** ＋「剖面」滑桿：右邊 3D 同步標出切在哪；勾「3D 剖切」直接看斷面，「換邊」換留哪一半。
- **模擬到**滑桿：只看做到第幾把刀為止。
- **圖層**（工具列）：快速 G0／切削／回原點路徑／素材，加一顆廢料下拉。刀路多的程式關掉 G0 最有感 —— 鑽孔板一類的程式，G0 常佔八成以上的線。
- **刀具**（工具列）：只畫勾選的刀。

### Block skip

三態：**關**（全部執行）／**開**（`/` 的節跳過）／**多斜線忽略**（`//` 以上永不執行、單斜線照跑）。切換後路徑、成品、檢查全部跟著換。R06 自動比較兩種情境，抓「某節被跳過之後，下一刀變成在材料裡橫著切」。

### 廢料判定

切穿之後跟工件分開的料（整圈切穿的外框、鋸斷的尾料）。**設定在素材子頁，顯示在視圖工具列**，兩件事分開。

- 哪塊是工件：自動（原點所在那塊）／原點／面積最大／碰到夾具／只看記號。判錯就在俯視圖點 ⊙（工件）或 ✕（廢料），記號優先於任何選法。
- 三個門檻：底皮多薄算切斷、多細的連接橋算斷、多小的碎片不標。
- **推估素材永遠判不出切穿**（推估底面比最深切削再低 5 mm），要看廢料就得填真實素材高度。四軸圓棒不支援。
- 廢料在碰撞判定裡仍然是實料 —— 它還在機台上，刀掃過去一樣會撞。「隱藏」只是不畫。

### 網址參數

```
index.html#sample=demo-plate&scenario=on&mode=sectionY&section=-20&tab=diag
```

另有 `split=0`（關掉 3D）、`clip=0`（只標平面不剖開）、`scrap=off|mark|hide`。網址只影響這一次瀏覽，不會存成偏好。

## 檔案結構

```
nc-preview/
├─ index.html          入口，依序載入所有 js
├─ css/                app（版面）editor panels view2d view3d
├─ js/core/            不碰 DOM 的核心，Node 可測
│  ├─ ns.js            型別定義（JSDoc）與共用小工具
│  ├─ tokenizer.js     斷行、斷字組、註解、節首斜線
│  ├─ interpreter.js   模態狀態機 → 動作序列
│  ├─ geometry.js      動作 → 線段；固定循環展開、刀徑補正、倒角圓角
│  ├─ tools.js         刀具推測、素材推估、刀具表存取、CSV
│  ├─ simulation.js    高度圖材料移除、碰撞與切削條件、時間估算
│  ├─ rules.js         跨模組的檢查規則（其餘由各模組就地發出）
│  └─ analyze.js       串起整條流程，合併去重排序診斷
├─ js/ui/              editor｜panels｜view2d｜view3d｜samples｜app
├─ samples/            示範程式（進版控）
├─ test/               node:test 測試
├─ tools/              開發腳本
└─ docs/CONTRACT.md    模組契約，改核心前先讀
```

載入順序固定：`ns → tokenizer → interpreter → geometry → tools → simulation → rules → analyze`，然後 `ui/*`，最後 `ui/app.js`。

**不進版控的本機資料**：`private/`（實際加工程式與現場資料）、`test/fixtures/`（golden test 用的實際程式）、`test/fixture-sim.*`、`test/shot-*.png`、`docs/proposals/`。沒有 `test/fixtures/` 時 golden test 整組自動 skip，其餘測試照跑。

## 開發

Node 22 以上。只用內建模組，沒有 `package.json`、沒有建置流程。

```bash
node --test "test/*.test.mjs"        # 全部測試（單一模組：test/rules.test.mjs）
node tools/check-samples.mjs         # samples/ 的示範程式不能有 error
node tools/make-samples.mjs          # samples/ 改過 → 重新產生 js/ui/samples.js
node tools/shot.mjs [範例[:hash]]    # headless 截圖到 test/shot-*.png，順便抓 console 錯誤
node tools/diag-report.mjs           # fixtures 的診斷總表（--no-sim／--cell／--all／--detail）
```

改核心模組前先讀 `docs/CONTRACT.md`，尤其最後一節「整合決議」—— 那些是踩過坑之後定下來的規則（G83 餘隙方向、倒角刀不能用公稱直徑當補正量、推估素材不報紅字…）。UI 模組用測試檔自帶的極小假 DOM 測純邏輯。

### 效能基準（回歸時拿來對）

1593 行 / 15 把刀 / 3582 段，兩個情境各跑一次模擬，Node 22 / Windows：

| 格距 | 格數 | 快照 | 快照佔用 | 整趟 |
|---|---|---|---|---|
| 0.5 mm | 0.17 M | 22 | 14 MB | 約 0.3 s |
| 0.25 mm | 0.68 M | 22 | 58 MB | 約 0.4 s |
| 0.1 mm | 4.27 M | 3 | 49 MB | 約 1.7 s |

不含模擬那一趟約 50 ms（契約目標 200 ms）。**快照份數是照位元組預算算的**（`settings.snapshotBudgetBytes`，預設 64 MB），不是固定份數 —— 固定 25 份的話，0.1 mm 光 heightmap 就會吃掉 750 MB。動過 `simulation.js` 的快照邏輯就要重量 0.1 mm 那一列。

## 已知限制

**解譯**

- G43 H 只檢查有沒有寫，Z 一律照程式值；G54–G59 視為同一原點。
- 只支援 G17；G18／G19 的圓弧退化成直線並警告。
- **M98／M99 副程式不展開** —— 那一段沒有預演，素材與碰撞結果不完整。要看完整路徑得先把副程式貼進主程式。
- G65／G66／G67 巨集、G68 旋轉、G16 極座標、G51 比例、G51.1 鏡像、G07.1 圓筒插補：認得、出警告、不模擬，也不會拿那一節的座標畫幽靈路徑。
- G92／G10 座標系位移不模擬；G53 不畫路徑；G95 只記狀態。
- 固定循環的 K／L：G91 照增量展開成多孔，G90 只畫一孔並警告（實機是原地重鑽，形狀一樣、時間會少估）。
- G87 背搪孔只近似；`,C`／`,R` 只展開接在直線後面的。

**第四軸（A）** —— 繞 X 軸的臥式分度頭，工件是夾在夾頭上的圓棒

- 五張圖同一套工件座標：**展開圖**（圓棒表面攤平，四軸先看這張）、**剖面 X**（橫截面）、**剖面 Y**（縱剖面）、**俯視**、**3D**（真正的圓棒成品）。
- 刀路都是直線，跟實機一樣（刀只走 XYZ，是工件在轉）。分度時刀相對工件掃過的那圈弧另外歸「工件轉動軌跡」，**預設不畫** —— 它容易被誤讀成「刀在轉彎」。
- 成品、殘料、碰撞都算得出來；做不到的是**側凹**（跟三軸的高度圖同一個限制）。
- **預設迴轉中心 Y0 Z0**（四軸標準對刀），不同的話到 Project → 機台填，跟著程式存。直徑留空＝由程式推估。
- 專抓：轉動時刀還沒退到安全高度（分度撞機第一名）、`A90` 沒小數點、補正生效中轉 A、程式結束沒轉回 A0、分度孔不在同一條母線上。
- 只支援位址 `A`，`B`／`C` 警告不模擬。連續四軸（A 與 XYZ 同動）連路徑都畫不出來，會標明。

**模擬**

- 材料是高度圖（每格記一個高度）：側凹、鑽穿之後的孔壁表現不出來。
- 格網只涵蓋素材的 XY 範圍 —— **完全落在素材外的治具（虎鉗鉗口）抓不到撞機**。
- 時間估算＝切削長度÷F ＋ 快速長度÷G0 速率 ＋ 停留，不含加減速、換刀、主軸啟停，實際會更久。
- 碰撞門檻：干涉小於 max(0.2 mm, 一格) 不報；下刀終點停在材料裡 >0.5 mm、路徑掃過材料 >2 mm 才是紅字，中間是警告（`settings.collisionIgnoreMm`／`collisionErrorMm`）。
- 廢料判定的解析度＝模擬格距，一道 0.4 mm 的牆在 0.5 mm 格距下判哪邊都有可能。

**介面**

- 軟極限只能從程式碼給（設定面板沒有欄位），所以 R33 平常不啟動。
- 「＋ 登記其他刀」的鄰居刀沒有直徑資料，只能當「該讓位」的一方；隔壁放的是別支程式的大徑刀就抓不到。
- 刀具表 CSV 裡 `8?` 這種「數字加問號」匯入時會跳過，但畫面會指出是哪幾把刀的哪一欄沒進來。
- 沒有折疊、沒有搜尋取代、沒有復原以外的版本管理。

## 要填哪些現場資料，結果才會準

程式檔只寫了「走到哪裡」，機台裡的東西它一概不知道。

1. **真實素材尺寸與擺放位置**（每支程式一組）—— 沒填就沒有廢料判定，靠素材的檢查全是警告。
2. **夾治具的位置與高度**（虎鉗、壓板、墊塊）—— 只抓得到落在素材範圍內的。
3. **刀具表實際值**：直徑、刀尖／倒角角度、刃長、伸出長。註解寫 12MM、實際裝 8MM 這種會直接改變補正後的路徑。
4. **各 D 號的機台現值**（半徑形狀與摩耗）。
5. **機台參數**：G0 實際速率、G83 餘隙（參數 5115，目前用 0.5 mm）、補正先讀節數（19625）、軟極限行程、刀庫刀位配置。
6. **G28 參考點在工件座標的位置**（目前用 X0 Y0 Z150 顯示）。

素材範圍和程式對不上（例如孔落在素材外面），通常是素材尺寸或原點位置填錯，不是程式有問題。
